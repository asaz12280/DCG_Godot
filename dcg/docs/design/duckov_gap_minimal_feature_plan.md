# Project DCG 與《逃離鴨科夫》功能種類缺口企劃書

Last updated: 2026-07-03

## 企劃目的

本文件用來分析 Project DCG 目前版本與 Steam《逃離鴨科夫》的核心功能差距，並整理成早期開發可以執行的企劃方向。

本階段不追求內容數量膨脹，不做第二張 Raid 地圖，不大量增加武器、敵人、道具或最終美術。目標是補齊「功能種類」：每個重要系統先做一個可見、可玩、可驗證的代表樣本，確認遊戲框架正確後，再用資料表和資源檔擴充數量。

## 參考遊戲功能摘要

Steam 商店頁將《逃離鴨科夫》定位為 PVE 俯視角撤離射擊遊戲，核心是離開基地後進入危險地點，搜集物資、面對敵人、生存並撤離。其公開介紹也強調藏身處建設、裝備升級、工作臺、武器改裝、技能樹、NPC 任務、五張地圖、隨機物資、敵人與天氣變化。

對 Project DCG 來說，現階段不需要追上五張地圖、50 種以上武器或大量任務內容。真正需要學的是它的結構：

```text
基地準備 -> 出擊探索 -> 搜刮/戰鬥/完成目標 -> 判斷撤離或貪更多 -> 結算 -> 把戰利品轉成長期成長 -> 下一場
```

## 目前 Project DCG 已具備的功能種類

依照目前專案文件與進度紀錄，Project DCG 已經具備以下早期功能：

- 3D Base：玩家能進入基地空間，並透過互動點開啟倉庫、任務、工作台與出擊流程。
- Raid 場景：玩家可進入第一張測試地圖，移動、瞄準、互動、搜刮與撤離。
- 容器格系統：箱子有自己的容量格，物品不會直接塞進背包。
- 背包與裝備 UI：玩家可開背包、看裝備欄、拖曳物品，並把手槍裝到主武器格。
- 武器與彈藥：No.5 手槍與 No.7 彈藥已能形成「取得 -> 裝備 -> 裝填 -> 發射」的基礎流程。
- 裝填與射擊可視化：有 R 鍵裝填、空槍自動裝填、裝填條、紅色 3D projectile。
- 撤離與結算：撤離後進入結果畫面，物品可回到基地流程。
- 倉庫、金錢、工作台升級：已具備最小型的基地成長骨架。
- 任務系統：已有收集/擊殺類任務與 Top Menu 任務頁。
- 敵人基礎：已有 scavenger 相關敵人資料與 AI/死亡/掉落的早期架構。
- 驗證工具：已有大量 `tools/validate_*.gd` 保護玩家可視流程、UI、裝備、裝填、射擊、基地與 Raid 串接。

## 核心缺口總覽

目前最大的問題不是「沒有內容」，而是很多種類只做到了最小骨架，還沒有形成玩家一眼能理解的完整撤離遊戲體驗。

| 功能種類 | 目前狀態 | 與《逃離鴨科夫》的差距 | 早期補齊原則 |
| --- | --- | --- | --- |
| 3D Base 功能站 | 有基地與互動點 | 功能站的角色感還不夠明確 | 每個功能站只做一個清楚用途 |
| 出擊前準備 | 有難度/基地/出擊 | 缺少出擊前資訊與風險提示 | 增加一個簡潔出擊簡報 |
| Raid 地圖目標 | 有撤離與搜刮 | 缺少地圖目的、熱區、撤離方向資訊 | 做一個地圖/撤離提示頁，不新增地圖 |
| 敵人種類 | 有基礎 scavenger | 缺少可辨識的戰鬥行為差異 | 先補一種遠程/巡邏型敵人即可 |
| 武器種類 | 有手槍、刀資料 | 缺少第二種戰鬥節奏 | 只補一種近戰或霰彈/慢速武器，不做武器庫 |
| 裝備種類 | 有裝備欄、護甲資料 | 護甲/背包效果還不夠玩家可感知 | 先讓一件護甲或背包明確改變數值 |
| 物資來源種類 | 有箱子與掉落 | 缺少特殊來源，如上鎖箱/任務物件 | 只做一種特殊箱或任務物件 |
| 任務種類 | 有收集/擊殺 | 缺少地點互動或帶回指定物 | 補一個「到指定點互動後撤離」任務 |
| 基地服務種類 | 有倉庫/工作台/販售 | 缺少治療、修理、補給、情報等服務感 | 只補一個服務站，例如醫療站 |
| 進度成長 | 有工作台升級 | 缺少讓下一場明顯不同的升級效果 | 一次只做一條很短的升級線 |
| 戰鬥回饋 | 有射擊與 projectile | 命中、受傷、敵人警戒仍需更清楚 | 補可見命中/受傷/警戒提示 |
| 損失壓力 | 有撤離/結算骨架 | 死亡損失、保險格、風險選擇需要更明確 | 先讓死亡與撤離結果差異一眼看懂 |

## 建議開發方向

### 原則一：先補種類，不補數量

每個系統只需要一個代表樣本：

- 一個基地服務站。
- 一種新敵人行為。
- 一種新任務型態。
- 一種特殊物資來源。
- 一種新裝備效果。
- 一個出擊簡報。
- 一個地圖資訊頁。

完成後再觀察是否真的好玩，再把同一套資料結構複製成更多內容。

### 原則二：所有內容都必須玩家看得到

如果系統存在但玩家正常遊玩看不到，就不算完成。之後每個任務都要有玩家可見完成條件，例如：

- 玩家可以走到功能站並看到提示。
- 玩家可以按鍵開啟對應 UI。
- UI 有繁中名稱、數量、用途或狀態。
- 玩家做出操作後能看到結果改變。
- 結果能進入保存/結算/下一場流程。

### 原則三：避免錯誤耦合

目前最需要保護的責任邊界：

- Base 只負責基地互動與出擊，不直接塞武器、補彈、掉寶。
- Raid 只負責本場行動、戰鬥、撤離與結果。
- Inventory 只管理背包格與堆疊。
- Equipment 只管理裝備欄。
- Weapon 只管理裝填、彈匣、射擊、projectile。
- LootContainer 只管理箱子自己的容量格與物品。
- UIManager 只管理 UI 開關、焦點、滑鼠模式與輸入阻擋。
- Quest 只管理任務狀態，不直接控制 UI 版面或玩家背包。

## Dev Slice 0.2 目標

Dev Slice 0.2 的目標不是變成完整遊戲，而是讓目前可視化 V2 版本變得更像一個真正的撤離遊戲。

玩家應能完成以下流程：

1. 從主選單選難度。
2. 進入 3D Base。
3. 在基地看見倉庫、工作台、任務板、醫療/補給站、出擊門。
4. 進入出擊簡報，知道本場目標、撤離方向、可能物資與危險。
5. 進入第一張 Raid 地圖。
6. 搜箱子，取得手槍、彈藥、基礎物資。
7. 打開背包，把手槍裝到主武器格，裝填子彈。
8. 遇到一名基礎敵人和一名不同行為的敵人。
9. 完成一個收集/擊殺任務，以及一個地點互動任務。
10. 決定撤離或繼續搜刮。
11. 撤離後看到結果，物品進入倉庫。
12. 在基地使用一個服務或升級，讓下一場有可見差異。

## 任務清單

以下任務按照優先順序排列。越前面的任務越應該先做。除非任務彼此不碰同一批檔案與責任邊界，否則不要並行。

### 任務一：建立 Dev Slice 0.2 驗收文件

目的：先把「種類補齊」寫成可驗收清單，避免 AI 自動化時變成亂加數量。

完成條件：
- 新增 Dev Slice 0.2 acceptance checklist。
- 明確禁止新增第二張 Raid 地圖與大量內容。
- 每個功能種類只允許一個代表樣本。

驗證：
- 文件中有玩家可見完成條件。
- 文件中有禁止擴量規則。

### 任務二：整理目前 V2 已完成系統與已知債務

目的：確認哪些是已完成，哪些是玩家還看不懂，避免重做已經存在的系統。

完成條件：
- 列出 Base、Raid、Inventory、Equipment、Weapon、Container、Quest、Enemy、Workbench、Result 的目前狀態。
- 標記哪些是「已可玩」、哪些是「存在但玩家感受弱」。

驗證：
- 對照現有 validation scripts。
- 不改 gameplay，只更新文件或驗證補強。

### 任務三：出擊前簡報 UI

目的：讓玩家在從基地進入 Raid 前知道要去哪、做什麼、怎麼撤離。

完成條件：
- 在 3D Base 出擊門前出現簡報面板。
- 顯示本場目標、地圖名稱、撤離提示、建議攜帶品。
- 全繁中，使用 Control/Container 節點優先。

驗證：
- `validate_raid_briefing_ui.gd`
- 1280x720 / 1920x1080 fit check。

### 任務四：地圖資訊頁補強

目的：Top Menu 的地圖頁要成為玩家能理解撤離方向與熱區的資訊入口。

完成條件：
- 地圖頁顯示目前地圖、玩家大概位置、撤離區方向、箱子/危險區提示。
- 不新增第二張地圖。
- 不要求精準小地圖，只要可讀的資訊面板即可。

驗證：
- `validate_top_menu_map_panel.gd`
- UI text quality validation。

### 任務五：基地功能站可讀性整理

目的：讓 3D Base 不只是能互動，而是每個站點玩家都知道用途。

完成條件：
- 倉庫、工作台、任務板、出擊門、服務站都有清楚互動提示。
- 打開 UI 後標題、按鈕、說明都是繁中。
- 功能站不直接寫入不屬於自己的資料。

驗證：
- `validate_base_interactions.gd`
- `validate_base_3d_runtime_hud.gd`
- `validate_base_station_readability.gd`

### 任務六：新增一種基地服務站

目的：補齊《逃離鴨科夫》類遊戲常見的基地服務種類，但不擴大量。

建議選項：醫療站。

完成條件：
- 玩家可在基地醫療站回復生命，或支付少量金錢補滿狀態。
- 不做複雜醫療系統、不做多種傷勢。
- 醫療站狀態與消耗清楚顯示。

驗證：
- `validate_base_medical_station.gd`
- Save/load safety check。

### 任務七：敵人行為種類補一種

目的：目前敵人種類感不足，需要一個和基礎 scavenger 行為不同的敵人。

建議選項：巡邏手槍敵人。

完成條件：
- 敵人會巡邏或站崗。
- 發現玩家後使用遠程攻擊。
- 玩家能看出警戒/攻擊狀態。
- 不新增大量敵人資料。

驗證：
- `validate_enemy_archetype_visibility.gd`
- `validate_enemy_ai.gd`
- `validate_combat_domain.gd`

### 任務八：戰鬥回饋補強

目的：讓玩家理解自己是否命中、是否受傷、敵人是否警戒。

完成條件：
- 玩家命中敵人有明顯回饋。
- 玩家受傷有明顯回饋。
- 敵人警戒或攻擊前有簡單提示。
- 不要求最終動畫。

驗證：
- `validate_combat_feedback_visibility.gd`
- Gameplay scene startup。

### 任務九：裝備種類補一種可感知效果

目的：裝備欄不只放槍，也要讓護甲或背包有明確玩法差異。

建議選項：輕型護甲。

完成條件：
- 護甲可裝到護甲格。
- 裝上後玩家防禦或受傷結果有可見差異。
- UI 顯示護甲提供的效果。
- 不做耐久、護甲等級、改裝等大系統。

驗證：
- `validate_equipment_armor_effect.gd`
- `validate_inventory_equipment_flow.gd`

### 任務十：特殊物資來源補一種

目的：箱子以外，需要一種不同的搜刮/互動來源。

建議選項：上鎖箱。

完成條件：
- 地圖上有一個上鎖箱。
- 需要鑰匙或任務條件才能開。
- 開啟後仍使用容器格 UI。
- 不新增多把鑰匙、不做多種鎖。

驗證：
- `validate_locked_container_flow.gd`
- `validate_container_inventory_ui.gd`

### 任務十一：任務種類補一種地點互動任務

目的：任務不能只有收集與擊殺，需要能引導玩家去地圖上的位置。

完成條件：
- 任務要求玩家到指定地點互動。
- 互動後任務狀態更新。
- 撤離或回基地後可完成。
- 任務顯示收納在 Top Menu 任務頁，不放回大 HUD。

驗證：
- `validate_location_quest_flow.gd`
- `validate_top_menu_panels.gd`

### 任務十二：死亡與撤離差異可視化

目的：撤離遊戲需要清楚讓玩家知道「活著撤離」和「死亡」差在哪。

完成條件：
- 成功撤離結果畫面顯示帶回物品。
- 死亡結果畫面顯示失去物品與保留項目。
- 玩家能從結果畫面回 3D Base。
- 不做複雜保險系統。

驗證：
- `validate_raid_result_panel.gd`
- `validate_raid_loss_rules.gd`
- `validate_raid_return_to_base_3d.gd`

### 任務十三：一條短基地升級線

目的：讓戰利品能變成下一場可見差異。

建議選項：工作台 Lv.1 -> 補給改善。

完成條件：
- 升級消耗木頭、電線、金錢。
- 升級後下一場有一個清楚差異，例如基地補給箱多一格、醫療站折扣、或出擊前資訊更完整。
- 不做多層科技樹。

驗證：
- `validate_base_progression.gd`
- `validate_three_raid_loop.gd`

### 任務十四：玩家可見 Dev Slice 0.2 Smoke Test

目的：把所有種類補齊成一條完整可玩流程。

完成條件：
- 3D Base -> 出擊簡報 -> Raid -> 搜刮 -> 裝備/裝填/射擊 -> 遇敵 -> 地點任務 -> 撤離/死亡結果 -> 3D Base。
- 每個新增種類都能被玩家正常看見與操作。
- 沒有新增第二張地圖，沒有大量內容。

驗證：
- `validate_player_visible_0_2_slice.gd`
- Standard Validation Set。
- UI 1280x720 / 1920x1080 fit check。

## 優先級

### 第一優先：讓玩家知道自己在做什麼

1. 出擊前簡報。
2. 地圖資訊頁。
3. 基地功能站可讀性。
4. 死亡/撤離結果差異。

### 第二優先：補齊玩法種類

1. 一種基地服務。
2. 一種敵人行為。
3. 一種裝備效果。
4. 一種特殊物資來源。
5. 一種地點互動任務。

### 第三優先：讓循環有成長感

1. 一條短基地升級線。
2. 下一場可見差異。
3. Dev Slice 0.2 smoke test。

## 不做清單

本企劃階段先不做：

- 第二張 Raid 地圖。
- 大量武器。
- 大量敵人。
- 大量任務鏈。
- 完整技能樹。
- 完整槍械改裝。
- 天氣系統。
- 最終角色/場景美術。
- Steam Workshop / MOD 系統。
- 多 NPC 對話系統。

## 最小可接受版本

本企劃完成後，Project DCG 應該具備以下狀態：

- 玩家可以不看開發文件，只靠遊戲內 UI 理解基地、出擊、任務、撤離、死亡、倉庫與升級。
- 每個主要撤離遊戲功能種類都有一個代表樣本。
- 系統之間沒有靠硬塞資料互相短路。
- 後續若要增加數量，可以優先增加資料資源，而不是重寫流程。
